记一次 Flutter 商户支付 App 的全链路协议逆向 —— 从三层检测到"当日流水"破案实录

发表于2026-11-02|更新于2026-11-02|逆向

本文记录一次完整的移动端安全研究过程：样本为某海外市场的商户收款 App（Flutter 开发），研究在自有测试账号与授权环境下进行。文中所有公司名、域名、账号、交易数据均已脱敏替换，相关漏洞与逻辑差异仅作学习交流，请勿用于未授权测试。

0. 写在前面

拿到样本的时候，需求很朴素：不打开 App，用纯协议把商户端的后端接口跑通——登录、收款码列表、交易流水、结算汇总，最好还能拿到”当天”的交易明细。

这篇文不讲工具怎么装，讲每一层是怎么破的、走了哪些死路、最后靠什么翻盘。尤其是最后一章”当日流水”的排查过程，堪称一次完整的排除法教学。

1. 样本解剖：没有壳的”壳”

样本是 .apks（split apks）格式，拆开后常规三步走：查加固、脱 Java 层、看 Native 库。

结论有点意外：

  • Java 层无壳，dex 直接可反编译；
  • 但主逻辑根本不在 Java 里——这是个 Flutter App，业务全在 libapp.so 的 Dart AOT 机器码中，Java 层只剩一个空壳 Activity 和几个桥接插件。

Dart AOT 是真正意义上的”壳”：没有字节码、没有常规符号，strings 出来全是垃圾。业界工具不多，我用的是 blutter——它能重建 Dart VM 结构、输出类/函数的伪代码和字符串池（pp.txt）。后面你会发现，这个字符串池成了整个项目最值钱的资产。

踩坑：blutter 编译 Dart VM 解析器在 Windows 上默认走 MinGW，ICU 库直接编译失败。换 VS2022 BuildTools 的 vcvars64 环境 + 微软版 cmake/ninja 一把过。

2. 三层检测体系：谁在盯着你

逆向 App 常态：先把这些”看门狗”找全，否则真机一跑就闪退。这个样本的检测是三层嵌套：

第一层：Native 层 su 扫描。 一个自定义命名的 checker so 里，启动时用 fopen 扫描 /sbin/su、/system/xbin/su 等一串 root 路径，命中即上报。

第二层：Java 层 RootBeer 全家桶。 经典的 9 项检测（su 路径、busybox、build.prop 关键字、SELinux 状态等）。

第三层：Dart 布尔门。 最阴的一手：前两层的结果通过 MethodChannel 回传 Dart，业务代码里用一个布尔值做整体门禁（app.dart 里一行 if (isRooted) { 退出 }）。

关键结论：三层都只查 root 痕迹，没有任何 hook 检测和反调试。这决定了绕过策略可以很暴力。

4. 抓包血泪史：流量到底去哪了

SSL pinning 是 Flutter App 的标配难题：BoringSSL 静态编进 libflutter.so，不走系统证书链，用户 CA 装了也白装。方案是 reFlutter 重打包（重编 libflutter 关掉证书校验）。

但打通之后 mitmproxy 里依然只有三方 SDK 的流量，业务流量凭空消失。排了三个坑：

  1. dart:io 的 HttpClient 不读 Android 系统代理——App 根本不知道你设了代理。得用 iptables 透明代理或者 reFlutter 的流量导出。
  2. 设备上有个”免费 VPN” App 一直活着，tun0 虚拟网卡 + fake-ip 模式把 443 流量整个劫走，force-stop 之后还会自启复活。每轮抓包前先杀它。
  3. PC 热点/同一 WiFi 的网络拓扑要对，别手机流量走 4G 还在等 mitm。

三个坑全平掉之后，登录全流程 8 个请求全部落盘。

后端是 Apollo GraphQL 网关（introspection 关闭）+ Keycloak 的标准组合。协议还原有几个必须靠实包校准的点（静态分析和实包的差异，全靠抓包纠正）：

登录四步链：

几个反直觉的细节：

  • OTP 是嵌套在 validateOtp 对象里随密码凭证一起提交的，不是独立接口；
  • source 字段的合法值不是猜的 “APP”/“ANDROID”，是 "NTP"（实包才看到）；
  • 请求头带 32 位随机样式的 x-app-clnt-id（客户端指纹）、x-dev-id（设备号），refresh 时旧 access token 不能出现在 Authorization 头里，否则服务端判 TOKEN_EXPIRED 死循环——这个坑让我 debug 了一小时。

令牌体系：access 15 分钟（RS256），refresh 179 天（HS256 Offline），且 refresh 是一次性轮换——每刷新一次旧 refresh 立即作废。这意味着会话文件只能有一份，复制出去两处跑会互相杀死。后来我还遇到服务端偶发返回非 JWT 的垃圾串，客户端必须做三段式 + iat/exp 校验，拒收保旧值。

6. 纯协议客户端与”当日流水”悬案

协议通了之后我写了个 CLI 客户端：密码/OTP 双登录、令牌自动续命、UPI 收款码列表、交易流水、结算汇总，全部实测通过。

然后甲方甩来一个问题：“App 首页明明显示今天收了一笔款，你的爬虫怎么没有？”

一查，已有流水接口（settlement 系）按清算日期过滤——当日交易 T+1 清算后才入列。而 App 的当日列表是实时的。数据差一天，这就是悬案。

7. 破案实录：当日数据到底藏在哪

这是全文最精彩的部分，完整记录排除法过程。

死路一：当日详情查询

先验证”知道交易号能不能当日查详情”。用 App 详情页展示的 Transaction ID 打详情接口——NOT_FOUND。当日数据在详情库里也不存在？存疑，先记下。

死路二：SSE 实时推送

反编译里明确有个 SSE 客户端（/subscriber/.../event），Headers 构造都还原了：Authorization: Bearer <token> + Accept: text/event-stream。协议侧直接连——401 INVALID_ACCESS_TOKEN，换了所有令牌变体都 401。

不甘心，用 frida 扫 App 进程内存（扫 JWT 特征字节 eyJhbGciOi），把 App 自己的活 refresh token 从 Dart 堆里抠了出来，换出全新 access token（scope 全齐）再连——还是 401。

顺手在内存里还扫出个彩蛋：一个硬编码在代码里的内部员工测试 token，签发于两年前，早过期了。当笑话看。

然后关键一击：登上手机看 App 自己的 TCP 连接——

对外只有一条 CLOSE-WAIT 的 SSE 残尸，官方 App 自己的推送也是断的。这不是我姿势不对，是服务端这个通道整个挂了。再 grep App 数据目录，当日交易号在磁盘上也不存在——那份数据只在内存里。

转机：回到字符串池

动态死路走绝了，回头静态。把 blutter 输出的字符串池（pp.txt）按业务域搜一遍，翻出一个从没在任何抓包里出现过的接口家族：

App 的 UI 代码里有完整的 GraphQL 查询原文——当日列表的真正数据源是 transactionSummary，根本不是 SSE。

最后一公里：三个参数坑

拿 transactionSummary 直接开打，一路被服务端”上课”：

  1. filters.dateRange 必填，且格式是 yyyy-MM-dd'T'HH:mm:ss（from 当天零点、to 当天 23:59:59.999）——这个 pattern 是从反编译里的 DateFormat 初始化函数挖出来的；
  2. filters.systems: ["PoS"] 必带——缺了不报校验错，直接 500（服务端空指针）；
  3. 最坑的：双编号体系。App 详情页展示的 “Transaction ID” 和接口用的交易号是两套编码！之前 NOT_FOUND 不是因为当日查不到，是 ID 用错了。用 transactionSummary 返回的 id 去打详情接口——当日当天，秒出 RRN。

终局：一步到位

还不满足：既然列表类型里能有 rrn 字段，能不能连详情请求都省了？把 rrn 直接塞进列表查询的字段选择里试一发——服务器认。最终形态：

当天的交易，一次请求，对账要素全齐。

8. 方法论沉淀

这次项目沉淀了几条可复用的经验：

场景 手法
Flutter AOT 无符号 blutter 重建；字符串池是最值钱的资产，接口家族全在里面
GraphQL introspection 关闭 空 {} 探测 + 报错驱动，服务端会自己把 schema 喂给你
通道疑似故障 先看官方客户端的 TCP 状态——官方也断就是服务端问题，别怀疑自己
需要真实请求样例 frida 内存扫 JWT/特征串，比 hook 一个可能错位的函数地址稳
“查不到”类问题 先怀疑 ID/编号体系，展示层和接口层的编号经常不是一套
偶发 500 / 空壳返回 网关后端有坏节点，退避重试即可，别急着怀疑参数

9. 结语

整个项目从拆包到纯协议客户端跑通，最耗时的不是绕检测也不是破 pinning，而是和数据口径搏斗：T+1 清算日 vs 交易日期、双编号体系、坏节点 500、SSE 服务端回归——每一个都足以让爬虫数据”缺一块”。

安全研究做到最后，拼的是排除法的耐心：动态死绝了回静态，静态挖出线索再回动态验证。循环两轮，没有破不了的案。
